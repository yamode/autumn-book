## 5. 旧マイページ動線をいつ・どんな条件で外すか

### 5.1 条件（すべて満たしたら外す）

1. **tripla 経由の予約で、まだチェックアウトしていないものが 0 件**（PMS の `core.stays` で `channel_code='tripla' and status in ('reserved','checked_in')` が 0。★Q7 の最終チェックイン日が目安）。
2. 1 を満たしてから **30 日**（領収書・ポイントなど宿泊後の問い合わせの猶予）。
3. tripla の契約終了日が確定している（終了後はリンク先が死ぬので、**終了日の前日までに外す**。こちらが先に来れば 1・2 を待たずに外し、文面を「お電話で」に変える）。

### 5.2 仕組み（外し忘れ・先に死ぬリンクを防ぐ）

- `LEGACY_MYPAGE_UNTIL`（日付・wrangler の vars）を**ローンチ時点で入れておく**（暫定値 **`2027-08-31`**＝最終チェックイン 2027-07-31 の約1か月後。ユーザー方針「全予約チェックアウト後にマイページを廃止・解約」に対応。★Q7 で最終日が確定したら見直す）。過ぎたらページの段が自動で「終了しました」に変わる＝リンクが死んだまま残らない。
- 実際に外す日は 5.1 で決め、`LEGACY_MYPAGE_UNTIL` を前倒しするだけ（コード変更なし・再デプロイのみ）。
- コードからの撤去（§7 P5）はそのさらに後。**「ご予約の確認」ページ自体は残す**（旧マイページの段だけ消える）。
- HP 側の SDK は tripla ボットの扱い（★Q4）と契約終了で決める。SDK を外すときは hp-oga の CSP から `https://tripla.jp` も外す。

## 9. 設計判断の理由（まとめ）

- **順番を「Book 公開 → HP 切替 → tripla 停止」にした**: どこからも予約できない時間を作らないため。各手順が独立に戻せる。
- **旧マイページは 1 枚の案内ページに集約（案 B）**: 期限付きの動線は足す場所と外す場所を 1 つにしたい。加えて Book には非会員・OTA 向けの「予約の確認」説明が無く、ローンチ直後に一番多い問い合わせがここに来る。
- **期限を環境変数で持ち、過ぎたら自動で文面が変わる**: tripla の契約が切れてリンクが死んだまま残るのが最悪。外し忘れを仕組みで防ぐ。
- **Book に tripla SDK は入れない**: CSP・同意バナー・GA の独立性を壊さない。旧マイページがウィジェットでしか開けないなら HP 側に SDK を残す。
- **DB 変更は切替に伴っては行わない**: 経路 `tripla`・支払方法・無料経路は既存予約が宿泊を終えるまで要る。統合は P4 で別途。
- **お知らせは Book の `/admin/news` で出す**: 両 HP が Book のお知らせ API を読む構成なので、HP のデプロイ無しに切替前後で文面を差し替えられる。
