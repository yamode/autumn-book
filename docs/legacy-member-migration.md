# 旧会員（tripla）の会員移行

- 作成: 2026-11-19（Book v0.289.0・autumn-shared `20261119115140_book_legacy_member_migration.sql`）
- 目的: 以前の予約システム（tripla）の会員が、**登録内容（氏名・カナ・電話・住所・生年月日）と、過去の公式・直販の利用回数**を引き継いで、Book の会員になれるようにする

## 1. お客様から見た流れ

1. Book のログイン画面・会員登録画面の下（両 HP はローンチ当日からフッター等）にある「**旧会員の方（会員移行）**」から `/auth/migrate` を開く
2. 以前登録したメールアドレスを入力すると、「該当すれば案内メールを送った」と表示される
   - 一覧に無い・既に移行済み・既に Book 会員の場合も、**画面の表示は同じ**（会員かどうかを外から探らせない）
3. 案内メールのリンク（`/auth/migrate/<トークン>`・**24 時間有効・1 回限り**）を開く
4. 以前の登録内容が入った画面で内容を確かめ、**新しいパスワード（12 文字以上）**を決めて「会員移行を完了する」
5. Book の会員になり、ログインした状態でマイページ（`/account?welcome=1&migrated=1`）へ。入会ボーナスも付く
6. 次回からは、メール＋パスワード、またはメールの確認コードでログインできる

## 2. 会員ランクへの反映（PMS の顧客マスタとの照合）

- 旧会員の一覧を取り込むと、**PMS の顧客（`core.guests`）と自動で照合**する（`book.legacy_match_guests`）
  1. メールが一致（`core.guest_identities` の email ／ `core.guests.email`）
  2. 1 で決まらなければ、**電話番号と氏名（漢字かカナ）がともに一致**
  - 候補が **1 人に絞れたときだけ**紐づける。複数当たったら紐づけず `match_note = 'ambiguous'`（人が確認）。該当なしは `'none'`
  - 個人以外の顧客（旅行会社など `guest_type <> 'individual'`）は対象外
- 移行の完了時、会員登録（`book.register_member`）の前に、照合済みの顧客へそのメールを紐づける（`book.legacy_member_prepare`）
  - 会員登録は確認済みのメールで顧客と名寄せするので、**会員はその顧客に紐づく**
- 会員ランクは「**通算の公式・直販の利用回数・泊数**」（`book._member_lifetime_stays`。公式サイト・直販・電話・tripla・予約番・FileMaker 時代の直販。OTA は数えない）で決まるため、**紐づいた顧客の過去の利用がそのまま反映**される。完了時にランクをすぐ計算し直す（`book.legacy_member_complete`）

## 3. tripla の会員一覧（CSV）の取り込み

1. tripla の管理画面から会員一覧を CSV で書き出し、Dropbox（`96_Claude/output/autumn-book-tripla/` など）に置く
2. Claude に「旧会員の CSV を取り込んで」と依頼する（列の名前を見て対応づける）
   - 取り込みは `book.admin_import_legacy_members(p_rows jsonb)`（service_role 専用）。1 行の形:
     `{"email","family_name","given_name","family_name_kana","given_name_kana","phone","zip","address","birthdate"(YYYY-MM-DD),"gender","raw":{元の行}}`
   - メールで上書き（移行済みの行は触らない）。不正なメールの行はスキップ。取り込み後に照合を自動で行い、件数（メール一致／電話＋氏名一致／要確認／該当なし）を返す
3. 照合の結果を確かめる（読み取りのみ）:
   ```sql
   select match_method, match_note, count(*) from book.legacy_members group by 1, 2;
   ```
   要確認（ambiguous）は、PMS で正しい顧客を確かめ、`matched_guest_id` と `match_method = 'manual'` を手で入れる（再照合でも上書きされない）

## 4. 守り

- 旧会員の一覧（`book.legacy_members`）と関数は **service_role 専用**。公開側（anon / authenticated）からは読めない・呼べない
- 案内メールのトークンは推測できない 32 バイト。DB には SHA-256 のハッシュだけを残す。リンク先は `no-store`・`referrer-policy: no-referrer`・`noindex`
- 送信の回数制限: Turnstile ＋ 1 IP あたり 10 分 10 回・1 メールあたり 1 時間 3 回（KV）・DB 側でも 1 メールあたり 1 日 5 通まで。完了の送信も 1 IP あたり 10 分 10 回
- 既に Book 会員のメールには送らない（通常のログインへ）

## 5. テストチェックリスト

- [ ] ログイン画面・会員登録画面の下に「旧会員の方（会員移行）」のリンクが出る（ja / en / zh-TW）
- [ ] 一覧にあるメールを入力すると案内メールが届く。一覧に無いメール・既に会員のメールでも、画面は同じ「お送りしました」の表示になる（メールは届かない）
- [ ] 案内メールのリンクを開くと、以前の氏名・カナ・電話が入っている
- [ ] パスワードが 12 文字未満・確認と不一致・プライバシーポリシー未同意だと、それぞれ止まる
- [ ] 完了するとマイページに入り、ログインした状態になっている。入会ボーナスが付く
- [ ] PMS で照合済みの旧会員は、過去の公式・直販の利用に応じたランク（シルバー以上）になっている
- [ ] 同じリンクをもう一度開くと「有効期限が切れているか、すでに使われています」になる。24 時間後も同じ
- [ ] 完了後、メール＋パスワードでログインできる（確認コードでのログインも使える）
- [ ] 短時間に何度も送ると「受付を一時的に止めています」になる
