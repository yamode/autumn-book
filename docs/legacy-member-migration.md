# 旧会員（tripla）の会員移行（手順書・v3）

- 状態: **受付を開けた**（2026-11-22・v0.303.0・`apps/web/wrangler.jsonc` の `LEGACY_MEMBER_MIGRATION=true`）。閉じるときは false にしてデプロイ
- 設計: `docs/legacy-member-migration-design.md`（v2・Fable のレビュー 2 回・v3）
- 実装: Book v0.290.0 ／ autumn-shared `20261119132049_book_legacy_member_migration_v3.sql`・`20261119132737_book_legacy_member_rematch.sql`・`20261119134010_book_legacy_member_review_fixes.sql`
- 目的: tripla の会員が Book の会員になり、**過去の公式・直販の利用回数を会員ランクに引き継ぐ**。住所・生年月日などは tripla から持ってこない（PMS の顧客マスタが正）

## 1. お客様から見た流れ

### 1.1 まだ Book のアカウントが無い人
1. ログイン画面・会員登録画面の「旧会員の方（会員移行）」から `/auth/migrate` を開き、以前のメールアドレスを入力（Turnstile あり）
2. 画面はいつも「該当すればご案内を送りました」（会員かどうかを外から探らせない）
3. 案内メールのリンク（`/auth/migrate/<トークン>`・**24 時間有効・1 回限り**）を開く → Cookie に入れて `/auth/migrate/continue` へ（URL からトークンを消す）
4. 氏名・カナ・**電話番号（必須・連絡先として保存するだけで照合には使わない・2026-11-22〜）**・パスワード（12 文字以上）・メール配信（**既定オン**・2026-11-22〜。会員登録画面と同じ）・プライバシーポリシーの同意 → 完了
5. 結果は 3 通り（マイページの表示と完了メールで伝える）
   - `linked`: メールと氏名が PMS の顧客と一致（照合が auto）→ その顧客に紐づけ、ランクを計算し直す
   - `pending_review`: 候補はあるが 1 人に決まらない（照合が candidate）→ 職員の確認待ち。会員登録はその場で済み、すぐ使える（その間は新しい顧客。確認が済んだら過去のご利用を引き継ぐ）
   - `new`: 該当なし → 新しい顧客

### 1.2 すでに Book のアカウント・会員がある人
- 案内メールは「ログインして引き継ぐ」（会員登録がまだなら続けて会員登録）。リンクでパスワードは設定しない
- ログイン後、マイページの「以前の会員のご利用実績を引き継ぐ」（`/account/legacy`）で**連絡先の電話番号**を入れる → `linked` / `pending_review` / `new`
- **通常の会員登録では、旧会員の一覧にあるメールを PMS の顧客に名寄せしない**（受信を確かめたメールで、この引き継ぎを通す）。必ずこの引き継ぎを通る

## 2. 会員ランクへの反映

- ランクは「通算の公式・直販の利用回数・泊数」（`book._member_lifetime_stays`。OTA は数えない）。紐づいた顧客の過去の利用がそのまま反映され、上がる方向だけ
- 照合（`book.legacy_match_guests`）: メールが一致する顧客のうち、氏名（漢字かカナ）も一致するのがちょうど 1 人 → `auto`。メールは一致するが氏名で 1 人に絞れない・電話＋氏名だけ一致 → `candidate`。それ以外 → `none`（2026-11-22・`20261121215657`）
  - 現役会員が付いている顧客・個人以外の顧客は対象外。完了・引き継ぎの直前に照合し直す
- 自動で紐づけるのは `auto`。**電話番号の一致は求めない**（案内メールのリンクを開けた＝そのメールの持ち主なので、本人確認はメールで足りる・2026-11-22 ユーザー指示）

## 3. 職員の確認（管理画面 `/admin/members/legacy`・管理者だけ）

- 「確認待ち」: 以前の登録（tripla）・**手続きで入力した氏名と電話**・PMS の候補が並ぶ。食い違いは赤字
  - 食い違うときは、**PMS に残っている電話番号へ宿から電話して本人か確かめてから**紐づける（メールの返信では確かめない）
  - 紐づけられるのは照合の候補の顧客だけ。確認待ちの間に予約していたら、紐づけるときに予約ごと照合の顧客へ統合する（`pms.merge_guests`・2026-11-22〜）。統合したものは「解除して元に戻す」ができない
  - 確信が持てないときは「紐づけない（却下）」（理由必須）
- 「紐づけ済み」: 自動で紐づけたものも職員が紐づけたものも全件出る。「解除して元に戻す」（理由必須）で、元の顧客・元のランクに戻る
- 操作はすべて `book.admin_audit_logs` に残る
- **注意: PMS の顧客の統合（重複チェック）は、この確認を通らない。** 旧会員の会員の顧客を統合するときは、別人を一つにしていないか PMS 側で確かめる

## 4. tripla の会員一覧（CSV）の取り込み

> ⚠ 取り込む前に、tripla との契約で会員の個人データが「委託」か「第三者提供」かを確かめる（6. 参照）。確かめるまで取り込まない

1. tripla の管理画面から会員一覧を CSV で書き出し、Dropbox（`96_Claude/output/autumn-book-tripla/`）に置く（git には入れない）
2. Claude に「旧会員の CSV を取り込んで」と依頼する。取り込みは `book.admin_import_legacy_members(p_rows jsonb, p_source text, p_purge_after date)`（service_role 専用）
   - 1 行: `{"email","family_name","given_name","family_name_kana","given_name_kana","phone","tripla_member_id","registered_on","mail_opt_in_at"}`。住所・生年月日・性別は入れない
   - メールで上書き（移行済みの行は触らない）。取り込み後に照合し、件数（auto / candidate / none）を返す
3. 結果の確認（読み取りのみ）: `select match_status, claim_status, count(*) from book.legacy_members group by 1, 2;`
4. `purge_after` を過ぎた未移行の行は、毎日 03:30（JST）に消える（cron `book_legacy_members_purge`）

## 5. 守り

- 旧会員の一覧と関数は service_role 専用（管理の関数は管理者だけ）。公開側からは読めない・呼べない
- トークンは推測できない 32 バイト。DB には SHA-256 だけ。リンク先は `no-store`・`no-referrer`・`noindex`
- 回数制限: Turnstile ＋ 1 IP あたり 10 分 10 回・1 メールあたり 1 時間 3 回（KV）・DB でも 1 メールあたり 1 日 5 通（どの案内メールも数える）・全体で 1 時間 300 通。**一覧に無いメールには何も送らない**
- 入口は本番ドメイン（book.yamado.app）と開発中の手元だけで開く（プレビュー・旧ドメインでは閉じる）。案内メールのリンクは本番ドメインで組み立てる（Host ヘッダは使わない）
- 完了の途中で失敗したらアカウントを消して戻す。ただし会員ができていれば消さない

  - 2026-11-22: メルマガに下書き「旧会員の新会員制度への移行案内｜下書き・未配信」（`c975b7d2-…`・西和賀の差出人・宛先は印「旧会員（tripla）」＝リスト「旧会員（tripla）・お知らせ専用」）。受付期間は【】のまま。ポイントは書いていない
  - 旧会員 1,988人をメルマガの宛先に取り込み済み。宛先にいなかった 1,588人は有効・印「旧会員（tripla）」「お知らせ専用」（同意なし）。もともといた 400人は印「旧会員（tripla）」だけ足した（配信停止・不達の 18人は状態そのまま）。移行案内の対象は 1,970人

## 7. テストチェックリスト

- [ ] 受付を閉じている間、`/auth/migrate` は準備中、ログイン・会員登録・マイページに入口が出ない
- [ ] プレビュー（*.pages.dev）では開いていても入口が閉じている
- [ ] 一覧にあるメールで案内が届く。一覧に無い・既に移行済みのメールでも画面は同じ（一覧に無いメールには届かない）
- [ ] リンクを開くとアドレスバーからトークンが消える。2 回目・24 時間後は「期限切れか使用済み」
- [ ] 電話が空だと止まる。メール配信のチェックは最初オン（外せば受け取らない）
- [ ] PMS の顧客とメール・氏名が一致する旧会員 → 電話番号が違っても、完了でその顧客のランクになる（マイページに「反映しました」）
- [ ] メールは一致するが氏名が違う → 「宿で確認のうえ反映」になり、管理画面の確認待ちに出る
- [ ] 管理画面で候補に紐づける → 会員のランクが変わる。解除 → 元の顧客・ランクに戻る
- [ ] 自動で紐づいたものも「紐づけ済み」に出て、解除できる
- [ ] 既に会員の人 → 案内メールは「ログインして引き継ぐ」。マイページの引き継ぎで電話を入れると反映／確認待ち
- [ ] 一覧にあるメールで通常の会員登録をしても、PMS の顧客には寄らない（マイページに引き継ぎの案内が出る）
- [ ] 短時間に何度も送ると「受付を一時的に止めています」
