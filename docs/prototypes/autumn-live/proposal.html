ふだんは静かで、動いたところだけが光る

山と川の風景をやめて、空だけを背景にしました。流れは「今日の累計を帯の太さ」「いまいる人を光の点」で描きます。どこで人が減っているかは一目でわかり、点の一つひとつが実際の一人です。数字は目標と、このペースでの着地点を並べて出します。目標から外れたときだけ色がつきます。下は推奨案をダミーデータで動かしたものです。

帯の太さ＝今日ここまで来た人数（全段で同じ縮尺） 光の点＝いまその段にいる一人 空へ上る点＝ここで離れた人 目標 このペースでの着地

段の間の％は次の段へ進んだ割合です。いつもの同じ曜日より大きく外れた段だけ、矢印と色がつきます。帯の下の細い線は今日の30分ごとの訪問で、薄い線がいつもの同じ曜日です。

いまの試作（v12）で見えにくいところ

読み取り
  • 川の太さが人数に比例していないので、どこで減ったかを読めない。「見方」パネルが必要になったのはこのため。
  • 流れ（中央）と数字（下のカード）が離れていて、目が行き来する。
  • 目標との差と「今日どこまで行きそうか」が流れの中にない。
見た目
  • 山・川・灯籠など比喩が多く、データより風景が目立つ。
  • 演出が常に動いていて、いつもどおりなのか何か起きたのかの区別がつかない。
  • 点が何を表すか（人なのか、件数なのか）が決まっていない。

集めた手本と、Autumn Live での使い方

業務ダッシュボードの古典、航空機のコックピット、工場の監視画面、話題になったライブ可視化から、ずっと見ていられて、しかも読める画面に効くものを選びました。

1画面で、比較つき

Stephen Few『Information Dashboard Design』・bullet graph

スクロールなしの1画面。数字は単独で出さず、目標と並べる。メーター型ではなく bullet graph を使う。

ふだんは暗く、異常だけ点く

Airbus「lights out」・ISA-101 高性能HMI

正常なら灯りが消えている、が航空機の原則。工場の画面も色は異常のためだけに取っておく。色は目標から外れたときだけ。

視野の端で感じる

Weiser ＆ Brown / Amber Case「Calm Technology」

壁に掛けて横目で見る画面。点の流れる速さ＝客足として周辺視野で伝え、注意を奪うのは予約などの出来事だけ。

いま・意味・この先

Endsley の状況認識3段階（知覚・理解・予測）

「いま何人」「いつもと比べて」「このペースだと今日は」の3つを1枚に。着地予測を目標の横に点線で出す。

点の一つひとつが本物

Shopify BFCM Live Globe・GitHub Globe

両社とも弧の1本が実際の注文や PR。作り物の飾りを流さない。光の点は実在の一人で、予約の点は最後まで追える。

減り方は帯で、推移は線で

Sankey（Minard 以来）・時系列との併用

Sankey は離脱点がすぐ見えるが、時間の推移は見えない。帯の下に24時間の線を添え、いつもの曜日を薄く重ねる。

縮尺は動かさない

Heer ＆ Robertson（アニメーションと知覚）

動きは単純に、軸の伸び縮みは知覚を乱す。帯の縮尺は1日固定で、数字は跳ばずに数え上がる。

遠くから読める

ArcGIS・Klipfolio の壁掛けダッシュボード指針

細部は遠目で読めない。主役の数字は大きく、補足は小さく、凡例なしでも読める言葉で書く。

鮮度を正直に

ThoughtSpot ほか「リアルタイム」の誤信

「ライブ」でも実際は数秒遅れる。右上に「何秒前の値か」を常に出し、途切れたら灰色にする。

3つの方向（どれも空だけを背景に）

推奨は A を主役に、B の24時間を細い線、C の bullet graph を下段にまとめたものです（上のライブ試作）。単独で選ぶこともできます。

A 推奨の主役

流れの帯

訪問から予約までを1本の帯で、施設を選んだところで2本に分ける。帯は今日の累計、点はいまの人。

強い
どの段で何人減ったか、いま誰がどこにいるか
弱い
時間の推移は見えない（線で補う）
B

一日の文字盤

24時間の輪に30分ごとの訪問を刻み、いつもの曜日を薄く重ねる。予約は輪の内側に金の点。

強い
一日のリズムと、いつもとの差。壁掛けで美しい
弱い
どこで離れたかは見えない
C

計器盤

旅客機の主計器のように縦の目盛りを並べ、目標を目印で示す。正常なら無彩色、外れた計器だけ色がつく。

強い
目標との差と異常に最速で気づける
弱い
動きが少なく、ずっと見ていたい感じは弱い

引き継ぐもの・やめるもの

引き継ぐ
  • 時間帯で変わる空（朝・昼・夕・夜）と、季節の降るもの（雪・花びら・紅葉・蛍）
  • 数字の数え上がり、目標の設定画面、予約の知らせと音、全画面・スリープ防止
  • 流入元として西和賀HP・男鹿HP・検索・SNS・直接の区別
  • 会員の総数・アクティブ率（下段の bullet graph に）
やめる
  • 山並み、川、湖、灯籠
  • 比例しない太さの流れと「見方」パネル
  • 常に動く演出（節目の波は、目標達成のときだけに）
  • 海外からの弧（数が少ないため、流入元の内訳に入れる）

この方向で進める場合

  1. 試作 v13 を推奨案で作り直す（docs/prototypes/autumn-live/）。空と季節の処理は v12 から移す。
  2. 段の定義を実データに合わせて確定する。「空室検索」「施設を選ぶ」が Book のどの画面・操作に当たるかを決める。
  3. そのうえで実データにつなぐ（Supabase Realtime と HP からの計測）。
