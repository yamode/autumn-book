# 客室アップグレード提案

## 仕様

- 公式サイト・yamado-oneの有効な会員本人の確定予約が対象。チェックイン日と現在の部屋タイプで対象を選ぶ。予約済みの各室単位で提案する。
- 管理画面 `/admin/upgrades` で、日付・現在の部屋・提案先・1室1泊あたりの税込追加料金・説明・通知方法・受付期限を設定。泊数を掛けた合計を対象者確認に表示する。無料または50円以上。
- 対象者を確認して送信。日時指定可。対象予約は送信登録時点で固定され、登録後に入った予約は含まれない。公開済み内容は変更せず、受付終了→新規提案とする。
- メール／アプリ通知／両方。メールは現在の確認済みAuthメール、アプリ通知は既存の受信設定・Expo Pushに従う。送信直前にも有効性を判定する。
- 会員専用 `/account/upgrades` と詳細ページで元の部屋・提案先の写真・追加金額・期限を確認し、明示的に同意して申し込む。案内の時点では在庫を確保しない。
- 元の支払方法を引き継ぐ。現地払いは確定後に現地精算。元の宿泊料金をオンライン決済済みの場合、追加分もオンライン決済。保存カードへ無断請求はしない。アプリからのオンライン決済は公式サイトで行う（ブラウザの会員ログインが必要）。無料は決済不要。
- 追加料金は元の宿泊料金・プラン・クーポン・ポイント・入湯税と別台帳。元の料金やキャンセル規定を変更しない。追加料金はポイント／クーポン割引対象外。

## 空室と決済

予約を先にロックし、全泊の対象在庫を検証する。現地払いでは旧室から新室への在庫振替と追加料金明細・確定通知を1トランザクションで作る。同じ申込の再送は同じ確定を返す。

オンライン払いは同意・決済開始時に新室を最大10分仮確保し、元の予約を維持する。Stripeの金額・通貨・用途・本人・DBとの紐付けをサーバーで照合して確定。期限内でも公開停止・予約変更・販売停止等を再検証する。ブラウザ終了時は署名付きWebhook、未処理は5分ごとの照合で回収する。

決済期限後または確定できない決済は追加分全額を返金し、仮確保を1回だけ解放する。通信・DBの一時エラーは安易に返金せず再試行する。返金処理中と返金完了は分けて管理する。期限切れ未決済はStripe取消後に照合済みを記録し、古い行が処理キューを占有しないようにする。

アップグレード料金だけの取消は不可。客室・予約の取消時はオンライン決済済み追加料金を全額返金する（宿泊料金のキャンセル料は既存規定）。部屋・日程・人数の自己変更は施設問い合わせに切り替える。施設スタッフによる変更後は別台帳の調整も運用で確認する。

## 連携と運用

- 共通migration: `autumn-shared/supabase/migrations/20261013000801_book_room_upgrade_offers.sql`。DB直接DDLは使わずリポジトリのmain連携で適用。
- 既存 `send-booking-mail` の施設SMTP・Vaultを利用。送信・確定メールの専用キューは最大5回再試行。SMTP成功とDB記録の間の障害では重複送信の可能性がある。
- `send-push` はアップグレード提案の期限・空室・予約状態を送信直前に再確認する。一般会員へ試験送信しない。
- PMSへ既存の客室変更電文を送り、部屋変更と追加料金・支払区分を滞在メモに記録する。**PMS請求書への追加料金・オンライン入金行の自動生成は含まれない。施設は別台帳とメモを確認して請求書へ反映する。**
- 既存のサイト全体メンテナンスは解除しない。yamado-oneはv0.14.0を配布・インストールして専用画面の実機動作を確認する。

## 検証

隔離PGliteで実migrationを実行し、権限・対象プレビュー・同意／金額改ざん・全泊空室・再送・原料金保持・オンライン仮確保・確定・期限切れ解放・取消返金キューを確認。Stripe通信を置き換えた実サーバーヘルパーで本人／金額照合・一時障害時の再試行・返金中／完了・未決済取消を確認。実課金・一般会員通知は実施しない。実カード／本人ログイン／SMTP受信／iPhone・Android端末での確認はHANDOFFのチェックリストで実施する。
